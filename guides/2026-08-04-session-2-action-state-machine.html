Action과
상태기계 골격

오래 걸리는 작업을 요청하고, 진행 단계를 feedback으로 보며, 한 번의 수동 취소까지 경험하는 두 단계 action 체인을 만듭니다. 오늘의 inner server는 로봇을 움직이지 않는 dummy입니다.

예상 약 2시간 ROS 2 Jazzy · Python RunTrial → PickPlace 실행 창 T0~T3
먼저 큰 그림

정상 action 흐름을 만들고 수동 취소를 한 번 경험합니다

Session 2의 목표는 모든 통신 장애를 막는 것이 아닙니다. goal이 두 action을 지나가고, stage feedback과 result가 돌아오는 정상 흐름을 이해한 뒤 manual cancel 한 가지만 확인합니다.

Step 4 · 약 10분

4manual cancel 한 번 확인

고의 오류 시험군은 만들지 않습니다. Action의 핵심 기능인 사용자 취소만 한 번 경험합니다.

4-1 · 실행 중 cancel 보내기

T1과 T2를 그대로 둔 상태에서 T3에서 실행합니다.

BashContainer (T3)
cd /workspace/pick_place_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 run pnp_evaluation scenario_runner \
  --cancel-after 0.8 \
  --run-id session2-manual-cancel \
  |& tee session2_manual_cancel.log

CANCEL_SENT reason=manual 뒤 RESULT status=CANCELED가 보이면 충분합니다. inner와 outer의 정확한 millisecond 경계, cancel timeout 예산, terminal 누락은 시험하지 않습니다.

정상 실행과 수동 취소의 차이를 확인했습니다.
