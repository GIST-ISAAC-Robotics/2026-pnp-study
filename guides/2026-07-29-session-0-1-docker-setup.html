Step A

AWSL2와 Ubuntu 24.04

먼저 Linux 기반과 WSLg GUI를 검증합니다. Docker까지 설치한 뒤 GUI 문제를 발견하면 원인 분리가 매우 불친절해집니다.

A-1 · 설치

PowerShell · 관리자Windows

재부팅 요청이 나오면 재부팅합니다. 첫 Ubuntu 실행에서 Linux 사용자 이름과 암호를 생성합니다. 암호 입력 중 화면에 문자가 보이지 않는 것은 정상입니다.

A-3 · 기본 도구와 WSLg GUI

BashUbuntu (WSL host) 
sudo apt update

git --version

DISPLAY는 정확히 특정 문자열일 필요는 없지만 비어 있으면 안 됩니다. xeyes 창이 Windows 바탕화면에 뜨면 성공이며 Ctrl+C로 종료합니다. x11-xserver-utils는 ROBOTIS 스크립트가 호출하는 xhost를 제공합니다.

A-4 · systemd 확인 후 필요할 때만 활성화

BashUbuntu (WSL host)

systemctl is-system-running

PID 1이 systemd이고 결과가 running 또는 degraded이면 아래 설정은 건너뜁니다. systemd가 아닐 때만 실행합니다.

Bash · 필요할 때만Ubuntu (WSL host) 
sudo tee /etc/wsl.conf > /dev/null <<'EOF'
[boot]
systemd=true
EOF
PowerShell · 설정 적용Windows 
wsl --shutdown

GUI 실패 순서: wsl --update → wsl --shutdown → Windows GPU 드라이버 확인 → ls /mnt/wslg 순서로 봅니다. WSLg 자체가 실패한 상태에서 Docker 설정부터 만지지 않습니다.

Step B

BDocker Engine 설치

이 수정본은 Ubuntu WSL 내부 Docker Engine만 표준 경로로 사용합니다. Docker Desktop은 대안이지만, 이미 선택했다면 아래 Engine 절차와 섞지 마십시오.

보안: 사용자를 docker 그룹에 추가하면 사실상 root급 권한을 부여합니다. 개인 개발용 WSL에서는 편리하지만, 공유 계정이나 신뢰할 수 없는 스크립트를 실행하는 환경에서는 이 의미를 알고 사용해야 합니다.

B-1 · 충돌 패키지 정리와 공식 apt 저장소

BashUbuntu (WSL host) 
# 빈 PC에서는 제거 대상이 없어도 정상입니다.
for pkg in docker.io docker-doc docker-compose docker-compose-v2 \
  docker-buildx podman-docker containerd runc; do
  sudo apt-get remove -y "$pkg" 2>/dev/null || true
done

sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt-get update

B-2 · 설치와 권한 반영

BashUbuntu (WSL host) 
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \

sudo systemctl enable --now docker
sudo systemctl status docker --no-pager

sudo usermod -aG docker "$USER"

그룹 권한을 확실히 반영하려면 WSL을 완전히 종료한 후 다시 엽니다.

C-5 · Zenoh router 전용 shell

Bash · 새 Ubuntu 터미널Ubuntu (WSL host) 
cd ~/open_manipulator
./docker/container.sh enter
ros2 run rmw_zenoh_cpp rmw_zenohd

rmw_zenoh_cpp의 기본 discovery에는 Zenoh router가 필요합니다. 마지막 명령이 실행 중인 동안에는 프롬프트가 돌아오지 않는 것이 정상이며, 이 shell을 router 전용으로 유지합니다. 작업할 명령은 원래 container shell에서 계속 실행합니다.

Bash · 생존 확인원래 Container shell 
pgrep -af '[r]mw_zenohd'
ros2 node list

container를 다시 시작할 때마다 router도 다시 시작해야 합니다. container.sh stop은 container를 제거하므로 router process도 종료합니다. 터미널 창만 남아 있어도 router가 살아 있다는 뜻이 아닙니다. 모든 stop → start 뒤 이 절차를 반복하고 pgrep로 확인하십시오.

D-2 · container 내부 실제 환경 확인

BashContainer 내부 
echo "ROS_DISTRO         = $ROS_DISTRO"
echo "RMW_IMPLEMENTATION = $RMW_IMPLEMENTATION"
echo "ROS_DOMAIN_ID      = $ROS_DOMAIN_ID"

ros2 --help > /dev/null && echo "ros2 CLI OK"

ros2에는 최상위 버전 출력 옵션이 없습니다. Jazzy의 CLI는 --help로 동작 여부를 확인합니다. ROS_DISTRO, CLI 실행 여부, 설치 package, ros2 doctor --report의 RMW 보고를 함께 기록해야 환경 변수와 실제 middleware를 모두 증명할 수 있습니다.

Unable to connect to a Zenoh router가 나오면 설치 실패가 아니라 router 미실행 상태입니다. C-5의 router 전용 shell을 실행하고 ros2 node list에서 같은 경고가 사라지는지 확인한 뒤 계속합니다.
