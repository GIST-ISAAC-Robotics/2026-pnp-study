Week 1 · Session 3 · Beginner Guide

URDF·TF2·ros2_control과
상위 launch

로봇의 뼈대, 움직이는 좌표계, controller를 실제 파일과 실행 graph에서 확인하고 Gazebo·MoveIt·project node를 한 명령으로 시작합니다.

예상 약 2시간 30분 ROS 2 Jazzy · Python launch world → end_effector_link 실행 창 T0~T2
먼저 큰 그림

따로 실행하던 층을 하나의 시스템으로 묶습니다

Session 3에서는 새 로봇 동작을 만들지 않습니다. 이미 검증한 Gazebo·MoveIt·Session 1~2 노드를 상위 launch 하나가 소유하게 만들고, 각 층이 URDF·TF·controller로 어떻게 연결되는지 읽습니다.

상위 launch

여러 package와 하위 launch의 시작 인자를 한곳에서 소유합니다.

구분 기준: URDF는 “무엇이 무엇에 연결됐는가”, TF는 “지금 서로 어디에 있는가”, controller는 “어떤 joint를 누가 읽고 움직이는가”, launch는 “이들을 누가 어떤 인자로 시작하는가”를 답합니다.

Step 1 · 약 30분

1실제 robot model과 controller 읽기

인터넷 그림을 외우지 않고 현재 설치된 ROBOTIS source에서 link·joint·planning group·controller 이름을 직접 찾습니다.

1-1 · 기준 package와 commit 확인

Bash · 읽기 전용Container (T2)
source /opt/ros/jazzy/setup.bash
source /root/ros2_ws/install/setup.bash

ros2 pkg prefix open_manipulator_description
ros2 pkg prefix open_manipulator_bringup
ros2 pkg prefix open_manipulator_moveit_config

git -c safe.directory=/root/ros2_ws/src/open_manipulator \
  -C /root/ros2_ws/src/open_manipulator rev-parse HEAD

세 package 경로와 기준 commit 32975f87efdb089e82c9ad103f068ef532aabfd2가 보여야 합니다. 다른 commit이면 이름을 추측하지 말고 실제 파일을 다시 읽습니다.

1-2 · URDF와 SRDF에서 frame·group 찾기

Bash · 읽기 전용Container (T2)
OM=/root/ros2_ws/src/open_manipulator
ROOT_XACRO="$OM/open_manipulator_description/urdf/open_manipulator_x/open_manipulator_x.urdf.xacro"
ARM_XACRO="$OM/open_manipulator_description/urdf/open_manipulator_x/open_manipulator_x_arm.urdf.xacro"
SRDF="$OM/open_manipulator_moveit_config/config/open_manipulator_x/open_manipulator_x.srdf"

grep -n '<link name="world"\|world_fixed' "$ROOT_XACRO"
grep -n '<link name=\|<joint name=' "$ARM_XACRO"
grep -n '<group name=\|<group_state name=\|<end_effector ' "$SRDF"
구분실제 값의미
Root / planning frameworld전체 pose를 해석하는 기준
Base linklink1world_fixed로 world에 고정
Arm chainjoint1~joint4 · link1~link5네 회전 관절의 연결
End effectorend_effector_link현재 EEF 기준 frame
Planning groupsarm, gripperMoveIt이 함께 계획하는 joint 집합

1-3 · ros2_control과 MoveIt controller 계약 읽기

Bash · 읽기 전용Container (T2)
HW="$OM/open_manipulator_bringup/config/open_manipulator_x/hardware_controller_manager.yaml"
MOVEIT="$OM/open_manipulator_moveit_config/config/open_manipulator_x/moveit_controllers.yaml"

grep -n 'joint_state_broadcaster\|arm_controller\|gripper_controller\|joint:' "$HW"
grep -n 'controller_names\|arm_controller\|gripper_controller\|action_ns' "$MOVEIT"

arm_controller는 joint1~joint4의 trajectory를, gripper_controller는 gripper_left_joint를 명령합니다. Right gripper는 left를 multiplier 1로 따르는 mimic joint입니다.

URDF·SRDF·controller 설정에서 실제 이름과 각 계층의 책임을 찾았습니다.

3-2 · node·controller·action graph 확인

Bash · 읽기 전용Container (T2)
cd /workspace/pick_place_ws
source /opt/ros/jazzy/setup.bash
source /root/ros2_ws/install/setup.bash
source install/setup.bash

ros2 node list --no-daemon | grep -x -E \
  '/controller_manager|/robot_state_publisher|/move_group|/rviz2_moveit|/target_pose_publisher|/target_pose_monitor|/pnp_orchestrator|/dummy_pick_place_server'

ros2 control list_controllers --spin-time 5
ros2 action list -t | grep -x -E \
  '/task/run_trial.*|/pick_place/execute.*|/arm_controller/follow_joint_trajectory.*|/gripper_controller/gripper_cmd.*'

ros2 topic echo /joint_states --once --timeout 10

세 controller가 모두 active이고 네 action이 type과 함께 보여야 합니다. /joint_states에는 arm 네 joint와 gripper joint가 포함됩니다.

3-3 · project node와 MoveIt의 sim time 확인

Bash · 읽기 전용Container (T2)
for node in \
  /target_pose_publisher \
  /target_pose_monitor \
  /pnp_orchestrator \
  /dummy_pick_place_server \
  /move_group
do
  printf '%s: ' "$node"
  ros2 param get "$node" use_sim_time
done

ros2 topic echo /clock --once --timeout 10

다섯 줄이 모두 Boolean value is: True여야 하고 `/clock` 메시지가 한 번 보여야 합니다. 커리큘럼의 필수 조건인 “모든 project node sim time”은 앞의 네 project node로 판정합니다.

3-4 · 상위 launch 안의 action chain 1회 확인

BashContainer (T2)
ros2 run pnp_evaluation scenario_runner \
  --run-id session3-upper-launch \
  |& tee session3_action.log

Session 2와 같은 stage feedback 뒤 RESULT status=SUCCEEDED success=true error_code=0이 보여야 합니다. Manual cancel은 이미 확인했으므로 반복하지 않습니다.

상위 launch 하나가 simulation·planning·project action을 함께 시작했습니다.
Step 4 · 약 25분

4TF tree를 읽고 frames.md 작성

URDF에서 읽은 고정 구조와 runtime TF를 연결합니다. 숫자를 외우는 것이 아니라 root·base·EEF 사이의 경로와 static/dynamic 차이를 설명하는 것이 목표입니다.

4-1 · world에서 EEF까지 runtime transform 확인

아래 명령은 계속 출력됩니다. Translation과 quaternion이 한 번 이상 보이면 Ctrl+C로 종료합니다.

Bash · 확인 뒤 Ctrl+CContainer (T2)
ros2 run tf2_ros tf2_echo world end_effector_link \
  |& tee session3_tf_echo.log

At time, Translation, Rotation이 보이면 world → end_effector_link 경로가 연결된 것입니다.

4-2 · 전체 TF diagram 생성

BashContainer (T2)
EVIDENCE=/workspace/pick_place_ws/session3_evidence
mkdir -p "$EVIDENCE"
touch "$EVIDENCE/COLCON_IGNORE"
cd "$EVIDENCE"

ros2 run tf2_tools view_frames
ls -lh frames_*.pdf frames_*.gv 2>/dev/null || true

생성된 diagram에서 world → link1 → link2 → link3 → link4 → link5 → end_effector_link가 끊기지 않는지 확인합니다. Fixed joint인 world_fixed와 end_effector_joint는 `/tf_static`, 회전·gripper joint는 `/tf` 관계를 만듭니다.
